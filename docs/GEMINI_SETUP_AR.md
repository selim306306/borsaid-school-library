# إعداد المساعدين الذكيين

## ما أُعدّ محلياً

- **مساعد الزوار:** يظهر أعلى الصفحة بعد الواجهة الرئيسية. يجيب من دليل أسئلة محلي، ويستعلم عن العناوين والإتاحة المنشورة فقط عبر `search_public_catalog`. لا يرسل السؤال إلى Gemini؛ تبقى المحادثة مؤقتة في الصفحة ولا تُحفظ بعد انتهاء الجلسة. يوضح أن الموقع لا يستضيف حالياً نصوص الكتب أو ملفات PDF، ولا ينشر أسماء العاملين أو مواعيد غير مؤكدة.
- **مساعد الموظفين:** دردشة إرشادية مرتبطة بوظائف الموقع، واختبار اتصال وملخصات جرد/إعارة/حجوزات. تتطلب جلسة موظف ودوراً مخولاً. الدردشة لا تقرأ قاعدة البيانات؛ لا ترسل إلا نص السؤال بعد موافقة واضحة. يوجد فحص خادمي لبعض أنماط البريد والهاتف والأرقام وسجلات الإعارة، لكن لا يمكن لفحص آلي أن يضمن اكتشاف كل اسم؛ لذلك لا تكتب أي بيانات شخصية أو حالة فردية.
- **مساعد مدير المكتبة:** يظهر للمالك والمسؤول فقط في مركز التشغيل، ويستطيع عند الطلب إنشاء ملخص للأعداد والإعدادات المجمعة فقط. لا يقرأ أسماء أو سجلات أفراد، ولا يعدّل القاعدة أو يرسل تنبيهاً.

هذه وظائف مصدر محلي. لم تُنشر Edge Function في Supabase، ولم يُضبط مفتاح Gemini أو `APP_ORIGIN` في أسرار المشروع؛ لذلك ميزات Gemini غير متاحة حتى يهيئها مالك المشروع ويختبرها. لا توجد تغييرات قاعدة بيانات مطلوبة لهذا التوسيع.

## التفعيل الاختياري لمساعد الموظفين والمدير

1. في مشروع Supabase `eahptkwvjcnixlzlyznh` افتح **Project Settings → Edge Functions → Secrets**، وأضف `GEMINI_API_KEY` كسرّ من داخل لوحة المشروع. لا تضع المفتاح في المحادثة أو SQL أو GitHub أو ملف الواجهة.
2. أضف `APP_ORIGIN=https://selim306306.github.io`؛ الأصل من دون المسار `/borsaid-school-library/` أو شرطة أخيرة.
3. اترك `GEMINI_MODEL` على `gemini-3.5-flash-lite` أو اختر نموذجاً مسموحاً في الواجهة. الأسماء المعتمدة في المصدر حالياً: `gemini-3.5-flash-lite` و`gemini-3.8-flash`.
4. راجع تغييرات المستودع أولاً. بعد اعتماد صاحب المشروع ونشر الملفات التي يعتمد عليها الموقع، يمكن نشر الوظيفة بالأمر:
   `supabase functions deploy library-assistant --project-ref eahptkwvjcnixlzlyznh`
5. أبقِ `verify_jwt = true` في `supabase/config.toml`، واختبر الاختبار الثابت والملخصات بحساب مخول بعد إعداد الأسرار.
6. قبل إتاحة الدردشة، ضع حدود استخدام ومراقبة تكلفة. لا تحتاج الوظيفة إلى `service_role`.

لا يحتاج مساعد الزوار إلى Gemini؛ فهو يعمل محلياً ويستخدم مسار الفهرس العام المقيّد. **لا توجد واجهة Gemini عامة مجهولة للموقع.** إذا طلبت الجهة لاحقاً إضافة توليد عام، فيلزم أولاً تصميم حدّ استخدام خادمي ومكافحة إساءة الاستخدام ومراجعة التكلفة والخصوصية.

## حدود الخصوصية والتشغيل

- اختبار الاتصال يرسل طلباً ثابتاً لا يتضمن بيانات المكتبة.
- ملخصات الموظفين والمدير تُبنى على أعداد/إعدادات مجمعة فقط بعد فحص جلسة Supabase والعضوية؛ ملخص المدير مقصور خادمياً على `owner` و`admin`.
- الدردشة ترسل نص السؤال فقط بعد موافقة كل مرة؛ لا تُرسل سجلات إعارة أو أسماء من قاعدة البيانات، ولا تُحفظ الرسائل في جداول الموقع.
- لا تكتب أسماء أو معلومات اتصال أو أرقام عضوية أو بيانات طالب/مستعير أو تفاصيل إعارة فردية إلى أي مساعد.
- الإخراج اقتراح إرشادي. أي تغيير أو نشر أو مراسلة يظل بيد الموظف ويحتاج مراجعة وموافقة مناسبة.
- أي تكامل Telegram مستقبلي اختياري وغير مفعّل: لم يُنشأ بوت ولم تُرسل رسائل ولم تُطلب أسرار. يتطلب إذناً صريحاً وإعداداً خادمياً آمناً وحدوداً وإيقافاً واضحاً قبل تشغيله.
