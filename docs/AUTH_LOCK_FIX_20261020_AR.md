# عزل الطلبات العامة عن قفل مصادقة الموظفين

## التغيير

أصبحت عملاء الفهرس والتحليلات والوسائط العامة تستخدم `accessToken: async () => null` بدل إنشاء GoTrueClient غير دائم الجلسة. هذا خيار يدعمه Supabase JS 2.57.0؛ عند إرجاع null يستخدم `fetchWithAuth` المفتاح العام، ولا يقرأ جلسة الموظف أو ينشئ عميل مصادقة إضافيًا.

لم يتغير عميل الموظفين: التخزين الافتراضي، قفل المتصفح، حفظ الجلسة وتجديدها والتعرف على رابط المصادقة باقية. لم تتغير قاعدة البيانات أو RLS أو الأدوار أو كلمات المرور أو بيانات المدرسة. تغييرات HTML هي بصمات موارد ولّدتها أداة version-assets فقط.

## ما ثبت في الاختبار

- نسخة الإنتاج السابقة تنشئ أربعة عملاء GoTrue في الصفحة وتعرض ثلاثة تحذيرات تعدد مثيلات. حزمة ESM المستخدمة تحمل auth-js 2.71.1؛ هذا الإصدار يستخدم navigator.locks افتراضيًا، حتى للعملاء العامة ذات persistSession:false.
- بحجز قفل جلسة الموظفين عمدًا في متصفح اختبار نظيف، بقي البحث العام قبل الإصلاح معلقًا حتى تحريره. بعد الإصلاح استجاب البحث أثناء بقاء القفل محجوزًا، واختفت تحذيرات تعدد العملاء. تحقق ذلك بعرضي 390 و1440 بكسل؛ RTL صحيح ولا تمرير أفقي، وطلبات الفهرس والوسائط ناجحة.
- في الفحص النظيف الحالي لم تظهر رسالة NavigatorLockAcquireTimeoutError القديمة كخطأ غير معالج. مصدر auth-js 2.71.1 يطلق هذا الخطأ إذا لم يتوفر القفل فورًا، ويعالجه في نبضة التجديد التلقائي؛ لذلك لا تثبت الرسالة التاريخية وحدها فشل تسجيل الدخول. أثبتنا مشاركة الأقفال وأزلنا تنافس العملاء العامة، لا سبب كل ظهور تاريخي للرسالة.
- محاولة بحساب اصطناعي غير موجود وصلت إلى خدمة المصادقة، ثم رُفضت برسالة طبيعية وعاد زر الدخول قابلًا للاستخدام، وظلت لوحة الموظفين مخفية. لم يُختبر دخول ناجح أو وظائف موظف بعد الدخول لعدم توفر اعتماد موظف مخول، ولا يجوز اعتبار اختبار الرفض دليلًا على نجاحهما.
- اختبارات Node: 297 ناجحة، دون فشل أو إلغاء أو تخطٍ. تشمل ثلاثة اختبارات جديدة لعزل العملاء العامة وبقاء إعدادات الموظفين وعزل كوكيز/مرجع التحليلات. فحص الصياغة وفحص بصمات الموارد ناجحان.
