# تحديث موارد الموقع والكاش

## قبل نشر تعديلات الواجهة

نفّذ من جذر المستودع، وأدرج التغييرات الناتجة في نفس commit:

```sh
node scripts/version-assets.mjs
node scripts/version-assets.mjs --check
node --test tests/*.test.mjs president-banner.test.mjs
```

تحتسب الأداة SHA-256 مختصرًا (16 خانة) للمحتوى الفعلي لكل CSS/JS/module محلي، ثم تحدّث `?v=` في صفحتي HTML والاستيرادات المباشرة والمتعدية، بما فيها قارئ Excel المحمل ديناميكيًا. يتغير إصدار الأب عندما يتغير إصدار تابع له. التشغيل الثاني بلا تغييرات لا يغيّر الملفات. `--check` للقراءة فقط ويعيد فشلًا إن نُسيت إعادة التوليد. ترفض الأداة دورات imports قبل كتابة أي شيء. لا تعالج الصور أو الشعارات أو PDF أو JSON أو عناوين الخدمات الخارجية، ولا تغيّر منطق التطبيق أو مصدر الأخبار.

هذه خطوة صيانة قبل النشر، وليست عملية تلقائية داخل GitHub Pages. أي تعديل مباشر من واجهة GitHub أو من أداة أخرى يجب أن يتبعه تشغيل الأداة وإرفاق مخرجاتها. لا توجد خدمة تعمل في الخلفية ولا Service Worker ولا reload تلقائي ولا تغيير لوسيلة النشر: تظل Pages من `main` وجذر المستودع مع `.nojekyll`.

## ما تحله وما لا تحله

تغيير URL المورد يمنع المتصفح من إعادة استخدام CSS/JS القديم لنفس URL عندما يستقبل HTML الجديد. توثيق [MDN للتخزين المؤقت](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Caching#cache_busting) يوصي بالإصدارات/بصمات المحتوى، ويفرّق بينها وبين إعادة التحقق من HTML نفسه.

في فحص 18 أكتوبر 2026، أعادت GitHub Pages للصفحة وCSS/JS والصور `Cache-Control: max-age=600`، مع `ETag` و`Last-Modified`. هذه ترويسات الاستضافة الفعلية وليست إعدادًا يمكن تغييره بوسم HTML. أكّد القياس تطابق HTML المنشور قبل الإصلاح مع `main` عند `1db1452`، ولم يُعَد إنتاج نسخة HTML القديمة وقت الفحص. لذلك مدة 10 دقائق تفسّر إمكانية التأخر، لكنها لا تثبت بأثر رجعي مصدر النسخة القديمة على هاتف بعينه. قد تبقى صفحة مفتوحة قديمة حتى يعاد تحميلها؛ وقد توجد فروق زمنية لانتشار النشر أو عقد CDN. روابط query لا تضمن إبطال نسخة CDN قديمة، ولا تضمن تحديث HTML.

بعد اكتمال النشر، افتح الرابط العادي في جلسة نظيفة دون query يدوي، وقارن bytes الموارد الحية مع commit. اختبر الرابط المكسور للكاش كتجربة إضافية، لا دليلًا بديلًا عن الرابط العادي. لا نعد بالتحديث الفوري: عادةً يمكن أن تبقى استجابة مخزنة صالحة لما يصل إلى نحو 10 دقائق من وقت تخزينها/إعادة التحقق منها، إضافة إلى انتشار النشر. للتحكم الصارم في HTML بـ`Cache-Control: no-cache` يلزم مستضيف يتيح ترويسات مخصصة؛ لم نغيّر الاستضافة ضمن هذا الإصلاح.

## إذا بقي التصميم القديم على الهاتف

أعد تحميل الصفحة أولًا بعد اكتمال النشر. إن استمر القديم، أغلق التبويب وافتح الرابط في تبويب خاص للتحقق دون بيانات التصفح المعتادة، أو انتظر نحو 10 دقائق وأعد التحميل. حذف بيانات الموقع هو حل أخير لأنه قد يزيل جلسة الدخول والتفضيلات؛ لا حاجة لحذف بيانات جميع المواقع. الصفحة القديمة المفتوحة لا تتغير وحدها.

## التراجع

استخدم `git revert <commit الخاص بإصلاح الكاش>` ثم انشر `main`. يجب إرجاع روابط HTML والاستيرادات المتوافقة معًا. لا يحتاج التراجع تعديل قاعدة البيانات أو الأذونات.
